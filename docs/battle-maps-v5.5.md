# v0.5.5 战斗地图缩放修复

## 已复现的原因

启动优化引入4×4的Phaser `__WHITE`纹理，占位背景调用`setDisplaySize(1600,900)`后，其`scaleX=400`、`scaleY=225`。Phaser `setTexture`更换帧尺寸时保留scale，随后换成1600×900地图但未再设置显示尺寸，实际背景变成640000×202500。玩家只看到地图中心很小的色块，树木与道路被放大到屏幕之外。图片加载成功和texture存在检查均无法发现这个问题。

已在新浏览器冷启动复现第三关，与用户“300金币建100金币法师塔后剩200、第一波、三倍速”的画面一致。错误由v0.5.3启动优化引入，前次修复首页及选关图片时未覆盖战斗背景尺寸。

## 修改

`BattleScene.setBackground`统一设置纹理、位置、锚点、1600×900显示尺寸和染色。所有战斗、返回首页、动作场、工坊背景切换都调用它，避免保留上一张纹理的缩放。规则、逻辑道路、塔位、单位、伤害、存档与编辑器作品均未更改。

## 验证

- `npm run test:battle-maps`：Chromium、WebKit，自动选择渲染器及强制Canvas，共104次关卡检查。每张地图必须是1600×900，scale为1×1，边界为0／0／1600／900，仅当前地图纹理保留。每三关返回首页再进入，覆盖占位纹理反复切换。
- 检查战场中央截图的色彩变化与源图，避免通过“资源存在”但只显示单色底的验收。逐张地图都检查实际绘制；第1、3、4、12、26关保存截图。工坊换背景和动作场另行检查。
- 第三关专项通过真实触控建造100金币法师塔，剩余200金币，手动开第一波，三倍速；使用发布构建及线上网页，并分别检查自动渲染与Canvas。前两关成绩只是隔离浏览器中的选关UI夹具，战斗资源和价格仍使用实际配置。
- 76项规则／编辑器快速回归，静态构建及原有手机交互继续检查。
