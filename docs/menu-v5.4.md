# v0.5.4 手机图片与关卡浮层

用户截图显示战役地图插画缺失，关卡说明挤成右侧窄条。前一版测试只验证元素边界、点击与按钮行为，没有验证说明面板实际宽度；窄条在已有截图中也存在，验收遗漏。

## 修复

- 手机战役已是一列网格，说明面板仍继承`grid-column:2`和`grid-row:2/4`。绝对定位浮层的包含块因此落到错误的网格区域。改为`grid-area:auto`，横屏宽360px、最大宽度为屏幕减16px；竖屏按左右安全区铺开。
- 内容保持垂直滚动，关闭与开始按钮可见；地图先完整展示，点关卡后才打开面板，关闭恢复地图。
- 首页、战役插画改用1280×720渐进JPEG：254480及292589字节，约为旧WebP体积的49%及41%。保留原插画，不生成新美术。`tools/prepare-menu-images.mjs`负责生成，`public/assets/menu-images.json`记录来源与格式。
- 图片加载失败自动尝试原WebP；两种格式均失败后显示“图片未能加载，请重试”与按钮。12秒仍未完成时显示下载慢提示。菜单按钮不等待图片下载；重试仅重新请求插画，不重置存档或战役。
- 插画和地图节点使用明确层叠顺序；加载状态有独立区域，避免只剩绿色背景而没有提示。无法直接确认用户手机上具体图片请求为何失败，兼容格式、减小文件和恢复入口覆盖下载／解码异常。

## 验证

`npm run test:menus`在Chromium与WebKit验证852×393、852×280、393×852、667×375、1024×768，三倍像素密度并模拟主屏幕独立窗口。852×393对应用户2556×1179截图的CSS尺寸。

检查图片实际完成解码、可见且截图像素有插画细节；说明面板至少320px（小屏按可用宽度）、在屏幕内、无横向溢出、可垂直滚动，开始按钮可达。另拦截JPEG验证WebP后备，拦截两种格式验证失败提示和重试。报告`test-results/menu-v54.json`，截图`test-results/menu-v54/`。

既有手机菜单测试补上图片实际加载与说明面板宽度断言；线上检查核对JPEG资源、实际显示与可用面板。规则与存档未改，真实手机逐机检查仍需实际设备。

本机结果：开发版和最终静态构建的Chromium、WebKit五种尺寸专项检查全部通过，包括两种图片故障恢复；手机建塔、八分支、缩放与声音回归通过；Chrome、Edge桌面交互和静态构建通过；76项快速测试通过。
