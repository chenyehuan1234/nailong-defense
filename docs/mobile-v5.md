# v0.5.3 手机触控、主屏幕启动与 GitHub Pages

v0.5.3将首页启动与战斗资源下载分开，并增加进度、失败重试和兼容显示。详细原因、数据与验证见 [启动修复记录](startup-v5.3.md)。本页保留此前手机布局与操作说明。

## 参考与布局

参考[Ironhide《Kingdom Rush》官方 iPhone 页面](https://apps.apple.com/us/app/kingdom-rush-tower-defense-td/id516378985)的移动平台定位，沿用横屏战斗、角落资源栏、英雄与技能快捷按钮、点塔后选择建造／升级的交互方向。具体尺寸、面板与菜单由本项目重新制作。

地图继续使用1600×900逻辑坐标，手机界面独立使用设备CSS像素。小屏或触控设备自动启用手机布局；主按钮至少44×44px。资源位于左上，自动开波、倍速、暂停位于右上，英雄和技能位于左下，开波位于右下。支持刘海与安全区。

选关、首页、设置、图鉴与升级树支持竖屏浏览。战役地图优先显示当前章节全图，点关卡打开敌情说明；章节按钮横向滚动，关卡选择器遵循原有解锁条件。说明和英雄区域独立滚动。升级树与长说明在小屏独立滚动。

## 手机操作

- 点塔位 → 选择塔；点已有塔 → 升级、分支、技能、出售。
- 点守卫营的集结点按钮后，面板收起；点范围内道路设置落点。
- 点英雄按钮 → 点道路附近移动。点怪物、英雄或士兵直接在底部显示生命、攻击、物抗和魔抗，没有“详情”按钮。
- 战场单指拖动、双指缩放；＋／−按钮调整视野，“适屏”恢复完整地图。滑动不触发建塔或英雄移动。
- 点援军或流星 → 点落点。右侧“取消”退出选点，手机无需键盘快捷键。
- 第一波手动开始，自动清场后3秒、1／2／3倍速与原作时钟模式仍沿用现有规则。
- 支持全屏的浏览器可点全屏按钮，尝试进入横屏；不支持的浏览器会显示“添加到主屏幕”的操作引导。
- 战斗中旋转到竖屏暂时停住战局，返回横屏恢复；已有的手动暂停仍保留。普通失焦不弹出暂停。
- 手机工坊使用可拖动标题栏、原生关卡选择器和可滚动表单，仍编辑完整26关模板。输入框和JSON可正常选择文字。

## 工程与存档

`viewport.ts`统一设备布局与坐标换算。Phaser输入仍映射逻辑坐标，建造、英雄移动、集结点和编辑器共用规则层。移动界面读取实时状态，未改动波次、伤害、经济与英雄数值。

`assets.ts`统一图片、音频和署名路径；Vite使用相对base，部署到项目路径后不会请求域名根目录下的assets。参考[Vite GitHub Pages部署说明](https://vite.dev/guide/static-deploy)。GitHub Actions从源码构建，部署到Pages；运行资产全部包含在构建中。

首次可信触摸中发起音频解锁与音乐播放，短音效在后台独立解码，不阻塞按钮或音乐。音乐仍流式播放，不随倍速变调。v4存档格式保持，当前本机进度不重置。GitHub站点和本机属于不同来源；若要迁移，在本机设置中导出存档，然后在线上设置中导入。手机和电脑的进度分别保存在各自浏览器中。

运行资产、内容、程序、测试、制作说明及资产来源记录纳入仓库；大型母版、下载原件和旧发布包保留本机，不参加线上构建。

## 验证

`tools/mobile-qa.mjs`使用独立浏览器存档，覆盖844×390、667×375、1024×768及390×844菜单：真实触控建塔、面板边缘限制、44px主按钮、技能取消、开波与三倍速、英雄移动、底部单位属性、集结点、旋转暂停恢复、手动暂停保留、竖屏菜单和手机工坊。

Chromium工坊拖动使用真实触控事件；WebKit校验触控操作和面板指针拖动。桌面Chrome、Edge交互与生产构建继续回归，76项规则／编辑器快速测试通过。报告位于本机`test-results/mobile*.json`，截图位于`test-results/mobile/`。这是浏览器触控仿真与WebKit引擎验证，尚未在真实iPhone、Android硬件上逐机测试。

## v0.5.1：上下工具栏与主屏幕启动

用户截图中的顶部标题／关闭按钮、底部返回／前进按钮是iPhone内置浏览器的原生界面，网页CSS和画布无法隐藏。交付增加`manifest.webmanifest`、180／192／512px本地奶龙图标与Apple主屏幕元数据；独立窗口使用与游戏一致的背景色、安全区和横屏方向。清单使用相对`start_url`、`scope`及图标路径，兼容GitHub Pages的`/nailong-defense/`路径。这个版本不承诺离线资源预缓存。

iPhone：Safari打开游戏 → 分享 → 添加到主屏幕 → 如有“作为Web App打开”则保持开启 → 从奶龙图标启动。独立窗口不显示浏览器的顶部标题栏、底部导航栏，系统状态与手势区域仍遵守系统规则。参见[Apple操作说明](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios)与[WebKit主屏幕Web App说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。微信／QQ等内置浏览器须先在系统浏览器打开链接；不能伪装一次网页按钮点击就消除它们的原生界面。

Android：支持网页Fullscreen API时战斗按钮直接进入全屏；否则提供Chrome／Edge菜单安装指引。若浏览器提供安装事件，指引可显示原生安装按钮。大地图、首页和设置提供“全屏游玩”入口；已经独立启动时隐藏重复安装入口。战斗安装引导暂停战局，关闭后保留原来的暂停状态。

短横屏以`window.innerHeight`同步壳层高度，避免动态工具栏改变后仍用旧高度；技能按钮的图标、名字和冷却文字合计高度小于按钮内部空间。自动开波缩短为“自动：开／关”。`tools/fullscreen-qa.mjs`在Chromium与WebKit覆盖844×268内置浏览器视口、844×390独立窗口状态、缺少Fullscreen API的安装引导、清单及图标资源、44px主按钮和技能文字完整性。截图与报告保存在`test-results/fullscreen/`和`test-results/fullscreen-v5.json`。

线上测试`tools/deployed-qa.mjs`验证GitHub项目资源路径、触控建造、开波、三倍速、刷新后设置保留和长音乐文件访问。Chromium验证长曲媒体解码；Windows无头WebKit没有提供AudioContext，使用HTMLAudio音乐后备通路。真实iPhone听感仍需硬件验证。

## v0.5.2：地图、简化菜单、直接属性与首次声音

首次加载完成后进入首页，手机使用现有冒险插画铺满屏幕；竖屏将标题和开始按钮移到下方，短横屏保留44px开始按钮。训练营推荐在点击开始冒险之后出现，不能遮住首次首页。

选关先展示当前章节的地图，按设备尺寸重新安排旗帜间距和连接线，避免44px触摸区域重叠；点旗帜或底部当前关卡栏打开关卡说明，再选择英雄、难度和开始。说明关闭后返回完整地图。这个布局仅改变选关界面的位置，26关道路、塔位与战斗坐标不变。

手机塔菜单使用本地塔缩略图、价格和少量操作图标，去掉伤害、射程、升级增量和文字段落。二三级、八种高级分支分别使用对应造型；技能用图标、价格和等级角标。未解锁分支、金币不足、技能满级仍按实际规则禁用。守卫营集结、出售返还、解除冰封和关闭按钮保留。`tools/prepare-tower-icons.mjs`从已有20帧塔图集导出透明64px缩略图，不依赖远程素材。

战斗视野与规则层分开：默认完整适屏，缩放范围1–2.5倍。单指位移超过8px视为拖动，双指始终视为手势；手势结束不会建造、选塔或移动英雄。坐标根据当前画布位置和大小反算。塔菜单保持屏幕内；英雄、技能或集结选点时收起缩放按钮，留出取消位置。手机战斗设置按钮可直接修改音量。

单位栏直接显示实时血量与攻击、物抗、魔抗；护甲读取当前诅咒或鼓舞后的实际数值。友军魔抗显示当前伤害规则实际使用的0%，不虚构抗性。点击关闭或单位死亡清除信息。

音乐清单在加载游戏时预取；首次触摸同步调用AudioContext.resume和媒体play，然后独立解码36个短音效。长音乐复用两个HTMLAudio元素，在首次触摸中预激活下一首所用元素，避免主题自动切换时重新创建未获播放权限的元素。保留1秒交叉淡化、原音量设置和同主题续播；缺少AudioContext时使用HTMLAudio播放音乐。浏览器要求用户手势时，通过首页“开启声音”或任意首次触摸启动，无需退出战斗返回首页。

`tools/mobile-experience-qa.mjs`覆盖Chromium和WebKit的844×390、844×268、390×844：首页先显示、插画铺满、选关地图适屏、说明按需展开、建塔价格与扣款、升级和八分支购买、技能按钮、缩略图加载、缩放与拖动。Chromium使用真实双指触摸验证缩放；WebKit验证触控点击和指针拖动。菜单测试使用隔离存档与9000金币的UI专用关卡，不能当作经济平衡或战役通关验证。

音频测试将短音效请求延迟6秒，并模拟每个媒体元素必须先由用户手势获准播放：首次触摸音乐在音效解码前启动，手势失效后自动切换Boss主题继续播放，最多两个音乐元素，零权限拒绝。Chrome和Edge连续音频测试保留流式播放、倍速不变调与密集音效限制。报告为`test-results/mobile-experience-v52.json`、`test-results/audio-soak-v4.json`，图片位于`test-results/mobile-v52/`。这些仍是浏览器仿真结果，真实手机的音频听感和系统工具栏须按设备复核。
