# v0.5.3 手机启动修复

## 原因与修改

用户报告多种手机浏览器停在“森林正在苏醒”。此前Phaser的preload队列在创建首页前请求51个图片文件，共35.69MiB，包括26张关卡地图、旧场景和18张PNG图集。首页依赖队列完成，界面没有真实进度和有效的失败恢复；请求缓慢、卡住或资源缺失均可能让玩家持续看见启动提示。之前的本机快速网络测试未覆盖这个条件。没有直接连接用户手机，不能断言具体哪一个请求失败。

- 首页先显示DOM插画和按钮，不等待战斗图集或关卡地图。
- 点击开始战斗、训练营或工坊时下载所需图集与当前地图。进入其他地图后释放旧地图的GPU纹理，避免26张地图常驻。
- 18张图集保持192px帧尺寸、透明度和锚点，输出WebP版本：PNG合计29.93MiB，WebP合计7.65MiB。压缩质量90，透明通道质量100；保留原PNG作为加载失败时的后备。制作脚本为`tools/prepare-runtime-sheets.mjs`，尺寸与字节记录为`public/assets/runtime-sheets.json`。
- 最多4个并发资源请求。加载层显示实际进度；35秒没有字节或文件进度时终止队列，单请求另有45秒超时。失败后不会创建半成品战局，可重试或返回首页，成功资源在重试中复用。
- 浏览器未提供WebGL时Phaser使用Canvas。初始化12秒未完成、初始化异常或WebGL上下文丢失时提供明确恢复提示；`?renderer=canvas`强制兼容显示。
- 音乐清单延迟到达时，在首次可信触摸结束／鼠标点击中使用项目自制静音WAV预激活两个长期复用的媒体元素。清单到达后接续长曲，短音效解码不阻塞音乐。
- 关卡、经济、波次、英雄规则及v4存档格式保持，未重置进度或工坊作品。编辑器、训练营及测试夹具等待异步资源后再进入场景。

## 验证

`npm run test:startup`在Chromium与WebKit触控视口覆盖：所有战斗图片被拦截时首页仍出现；失败不创建战局；解除拦截后重试可建塔、开波；仅请求当前关地图；WebP失败自动使用PNG；无WebGL时Canvas正常战斗。另将地图请求完全挂起，验证35秒无进度超时及重试恢复。记录在`test-results/startup-v53.json`，截图在`test-results/startup/`。

手机操作、桌面Chrome／Edge工坊及单位信息继续回归。音频测试将音乐清单延迟6.5秒、短音效延迟6秒，首次触摸发生在清单到达前：音乐在音效解码前播放；用户手势过期后切换主题仍使用原两个媒体元素，没有权限拒绝；已有静音设置仍生效。

本机最终检查：76项快速规则／编辑器测试通过；Chrome、Edge依次进入全部26张地图，零脚本或资源错误；两种浏览器的工坊和单位交互回归通过；静态构建在Chrome／Edge通过，Chromium与WebKit短横屏和兼容显示通过。`npm run build`成功，构建中包含本地WebP及PNG后备，不依赖远程热链。

线上检查由`tools/deployed-qa.mjs`核对版本、首页不请求战斗图、只加载当前地图、压缩图集可访问、触控建塔与倍速、设置保留和首次音乐。以上是浏览器触控仿真、故障注入与WebKit引擎验证，不代表已经逐台验证真实iPhone、Android或微信内置浏览器。
